# Монитор заявок trader.gaz.trade (Amvera)

Бот следит за страницей `/payouts/available`, присылает новые заявки в Telegram
всем пользователям сразу и умеет брать заявку в работу прямо из уведомления.
Вход на сайт (логин, пароль, 2FA) проходит в чате с ботом, сессия создаётся
на сервере Amvera и лежит в постоянной папке `/data`.

## Файлы для загрузки в репозиторий Amvera

| Файл | Зачем |
|---|---|
| `main.py` | Telegram-бот: меню, уведомления, кнопка «Взять в работу», вход, мониторинг |
| `browser.py` | Playwright: проверка страницы, взятие по API или кнопкой, автоматизация входа |
| `cards.py` | Разбор карточки заявки, оформление уведомления, сердечки банков |
| `registry.py` | Список заявок: актуальные и устаревшие |
| `users.py` | Кто может пользоваться ботом: основные и добавленные аккаунты |
| `autotake.py` | Автовзятие: фильтры (способ оплаты, диапазоны сумм), хранение и проверка заявки |
| `fastlane.py` | Быстрая линия: API сайта напрямую — список, push по WebSocket, взятие одним запросом |
| `config.py` | Настройки и переменные окружения |
| `storage.py` | Атомарная запись JSON в `/data` |
| `requirements.txt` | Python-зависимости |
| `Dockerfile` | Образ с Python + Chromium |
| `amvera.yml` | Конфигурация Amvera (Docker, папка `/data`) |
| `.dockerignore`, `.gitignore` | Чтобы в образ/репозиторий не попал мусор |

`auth_state.json` и `seen_requests.json` загружать **не нужно**. Бот создаёт `auth_state.json`
сам после входа. `seen_requests.json` из прошлой версии больше не используется.

## Развёртывание

1. В Amvera: «Создать» → тип сервиса **Приложение**.
2. Загрузи все файлы выше в корень репозитория (через git или интерфейс).
3. Вкладка «Переменные»: добавь секрет `TELEGRAM_BOT_TOKEN`.
4. Дождись статуса «Успешно развёрнуто» (первая сборка ~3–6 минут: ставится Chromium).
5. **Каждый аккаунт** должен открыть бота и один раз нажать `/start`.
   Иначе Telegram не даст боту писать этому аккаунту.
6. С любого аккаунта: «🔐 Вход» → логин → пароль → код 2FA. Сессия общая.

Chromium нужен ~500–700 МБ памяти — выбери тариф с запасом по RAM.

## Что умеет

* **Уведомление о новой заявке** приходит одновременно всем пользователям.
  По номеру телефона (СБП):

  ```
  🆕 Новая заявка!

  Способ оплаты: СБП
  📞 +79064156725
  💵 40 000,00 ₽
  🟢 Сбербанк

  Ссылка на сайт: https://trader.gaz.trade/payouts/available
  ```

  По номеру карты: «Способ оплаты: По номеру карты» и `💳 2202201954097339`.
  Телефон или карту бот определяет по самому реквизиту (длина, начало, контрольная цифра).
  Сумма с копейками, курса и пустых строк нет. Реквизит нажимается и копируется. Так же выглядят
  заявки в «📋 Списке заявок».
* **Кружок у банка:** Т-Банк 🟡, Сбер 🟢, Озон 🔵, ВТБ 🔵, Альфа 🔴, ПСБ и Промсвязьбанк 🟣,
  ЮMoney 🟣, остальные без кружка. В Telegram нет голубого кружка, поэтому у ВТБ и Озона один и тот же 🔵.
* **Кнопка «✅ Взять в работу»** есть под уведомлением и под каждой заявкой в «📋 Списке заявок».
  Бот нажимает кнопку на сайте и смотрит на список там: заявка пропала — успех, осталась — ошибка.
  * **Взялась.** Всплывает «✅ Заявка взята в работу». В чате нажавшего приходит ответ
    на заявку. Остальным приходит «✅ Имя взял(а) в работу заявку». В самой заявке у всех
    кнопка заменяется строкой «✅ Взята в работу — Имя».
  * **Не взялась.** Всплывает «❌ Не взялась: причина». В чате приходит сообщение с причиной —
    текст самого сайта (всплывашка или `alert()`) либо «Сайт не взял заявку: она осталась в списке».
    Если сайт ничего не написал, к сообщению добавляется скриншот страницы.
    Кнопка остаётся, можно нажать ещё раз.
  * Если сайт просит подтверждение (окно или `confirm()`), бот подтверждает.
* **«📋 Список заявок»** показывает только актуальные заявки. Когда заявка пропадает с сайта
  (две проверки подряд), её сообщение исчезает из списка, а уведомление о ней получает пометку «⌛ Устарела».
* **Скорость.** Страница обновляется примерно раз в 5 секунд (`SCAN_INTERVAL`). Период считается
  от начала проверки, а сама проверка занимает 1–2 секунды: бот ждёт не «тишины в сети»
  (на некоторых сайтах это всегда 10 секунд), а пока данные появятся и перестанут меняться.
  Если сайт начнёт ограничивать запросы, поставь `SCAN_INTERVAL=10`.
* **Слёт сессии.** Бот один раз пишет «⚠️ Сессия на сайте слетела…» с кнопкой «🔐 Вход» и
  больше не напоминает. Кнопка открывает вход (логин → пароль → 2FA). Когда сессия вернулась,
  кнопка у сообщений пропадает. Вход одновременно проходит только один аккаунт.

## Автовзятие

Кнопка **«⚡ Автовзятие»** в меню (или `/auto`, или кнопка под «📊 Статусом») открывает настройки.
Все кнопки нажимаются прямо в сообщении, оно обновляется на месте.

* **Включить / выключить** автовзятие одной кнопкой. Остальным пользователям придёт сообщение об этом.
* **Способ оплаты:** СБП и/или «По номеру карты» (можно выбрать оба).
* **Суммы:** 3 000–3 999, 4 000–4 999, 5 000–5 999, 6 000–6 999, 7 000–7 999, 8 000–8 999,
  9 000–10 000, 10 000–15 000, 15 000–20 000. Можно выбрать несколько, есть «Выбрать все» и «Сбросить».
* Заявка берётся сама, только если подошли **оба** фильтра. Если не выбран способ оплаты или
  диапазон, автовзятие ничего не берёт, а включить его без фильтров бот не даст.
* Суммы считаются в целых рублях: заявка на 3 999,60 ₽ попадает в «3 000–3 999», границы включительные
  (10 000 ₽ подходит и под «9 000–10 000», и под «10 000–15 000»).
* В **«📊 Статусе»** есть строка «⚡ Автовзятие: включено ✅» с выбранными фильтрами.
* Настройки общие и хранятся в `/data/autotake.json`.

**Как это работает.** Пришла новая заявка:

* **Подходит под фильтры.** Бот сразу начинает нажимать кнопку на сайте и одновременно рассылает
  уведомление «⚡ Пытаюсь взять в работу…» (без кнопки). Потом результат:
  * успех: «Откуп в корзине, шеф 🤗». Сообщение дополняется у всех, и приходит ответ на заявку;
  * неудача: «Извините, шеф, неудача 😔» и причина (текст с сайта или «заявка осталась в списке»).
    Кнопка «Взять в работу» возвращается, чтобы можно было взять вручную. Если заявку уже
    забрали, кнопки нет. Каждую заявку бот пробует взять сам не более двух раз.
* **Не подходит под фильтры или автовзятие выключено.** Всё как раньше: обычное уведомление с кнопкой
  «Взять в работу», заявка в «📋 Списке заявок».

Автовзятие касается только новых заявок. То, что уже висело на сайте при включении и при
первой проверке после запуска, бот сам не берёт. Заявки с непонятным реквизитом, не в рублях или
без суммы всегда приходят с ручной кнопкой.

## Быстрая линия (прямой доступ к API сайта)

Код сайта открыт, поэтому видно, как он работает, и бот делает то же самое, но напрямую:

| Что | Как сайт это делает | Что делает бот |
|---|---|---|
| Список заявок | `GET api-trader3.<домен>/account/payouts/available` | Опрашивает этот адрес сам, все страницы сразу |
| Новые заявки | WebSocket `wss://ws-trader.<домен>`, канал `@traders/available_payouts`, событие `ADD` | Слушает тот же канал: заявка приходит за десятки миллисекунд |
| «Взять в работу» | `PATCH …/account/payouts/{id}/assign` | Отправляет этот запрос, без страницы и клика. Ответ 2xx — заявка за вами |
| Авторизация | `Authorization: Bearer <idToken>` (AWS Cognito) | Берёт токен из браузера, где бот уже вошёл, и обновляет его так же, как сайт |

Ничего настраивать и «обучать» не нужно: адреса, поля и тексты ошибок взяты из кода сайта. Запросы
отправляются из отдельной лёгкой вкладки в том же браузере (тот же Origin и те же cookie), поэтому
для сервера это обычный клиент. Эта вкладка не мешает проверке страницы и не ждёт её.

**Что получается.**

* Новая заявка приходит по WebSocket. Если она подходит под автовзятие, бот сразу отправляет `PATCH`.
  Если нет, мгновенно приходит уведомление с кнопкой. Кнопка «Взять в работу» тоже работает через API.
* Опрос списка при работающем push нужен только как страховка (раз в 3 с, `FAST_PUSH_POLL`), без push
  опрос идёт раз в секунду (`FAST_INTERVAL`). Именно список ведёт реестр и помечает заявки устаревшими.
* Страница целиком перепроверяется раз в 15 секунд (`FAST_AUDIT_INTERVAL`): это проверка, что вход
  не слетел, и сверка с API.
* Ошибки сайта приходят по-русски: «заявку уже взял другой трейдер», «сумма заявки превышает ваш лимит»,
  «ваш аккаунт заблокирован для взятия заявок», «ваш аккаунт не подключён к мерчанту этой заявки» и т. д.
* **У заявок по карте в данных сайта нет банка** (только номер карты), поэтому у них нет строки
  с банком и кружка. У заявок по СБП банк есть.

**Предохранители.** Если что-то не сошлось, бот пишет об этом основным аккаунтам и работает как раньше
(страница и клик):

* сайт ответил 401/403 — токен пробуется обновить, не вышло — быстрая линия ждёт, вход проверяет страница;
* ответ 429 (слишком часто) — пауза 30 секунд;
* всё, что нарисовано на странице, должно быть и в списке API; если расхождение держится четыре проверки
  подряд, быстрая линия отключается на 10 минут;
* если страниц в списке больше десяти, «устаревшими» заявки не помечаются.

**Первый запуск.** Прошлые версии видели только заявки с первой страницы списка. Поэтому первый полный
снимок API бот запоминает без уведомлений, а дальше присылает только новые.

**Состояние:** «📊 Статус» или `/fast`. Выключить целиком: `FAST_LANE=0`.

**Что нельзя проверить заранее.** Я не видел настоящих ответов сервера и не мог войти в аккаунт, поэтому
проверял на копии сайта с тем же контрактом. Если у сайта окажутся другие параметры списка или он
откажет в доступе, быстрая линия отключится сама, и бот останется на странице и кнопке.

## Пользователи

Основные аккаунты заданы в `config.py` (`CHAT_IDS`, по умолчанию три твоих). Только они могут
добавлять и удалять остальных. Остальные пользуются ботом так же, как основные.

* **«📊 Статус» → «➕ Добавить пользователя»** (или `/adduser`), затем отправь:
  * **числовой ID** — доступ открывается сразу, пользователю уходит приглашение;
  * **@username** — доступ откроется, когда этот человек откроет бота и нажмёт `/start`
    (Telegram не позволяет боту найти человека по имени заранее). Ожидание действует 7 дней,
    основные аккаунты получат сообщение, когда человек подключится.
* **«📊 Статус» → «👥 Пользователи»** (или `/users`) показывает всех и позволяет удалить кнопкой ❌.
* Список хранится в `/data/users.json` и переживает перезапуски.
* Чтобы уведомления доходили, каждый добавленный должен хотя бы раз нажать `/start` у бота.

## Что считается «той же самой заявкой»

Сумма, банк и реквизиты. Курс и прочие меняющиеся поля не учитываются, поэтому
изменение курса не создаёт «новую» заявку. Заявка считается устаревшей, если пропала
с двух проверок подряд (защита от случайного сбоя загрузки страницы). Если такая же
заявка появилась снова после того, как пропала, это новая заявка.

## Если форма входа определилась неверно

При ошибке бот присылает скриншот страницы входа. Тогда задай переменные
(CSS-селекторы) и перезапусти приложение:

| Переменная | Что указывает |
|---|---|
| `LOGIN_URL` | адрес страницы входа, если сайт не редиректит сам |
| `SEL_LOGIN` | поле логина, например `input[name="email"]` |
| `SEL_PASSWORD` | поле пароля |
| `SEL_OTP` | поле кода 2FA |
| `SEL_SUBMIT` | кнопка отправки формы |

Прочие переменные: `CHAT_IDS` (основные аккаунты, id через запятую; по умолчанию три твоих),
`FAST_LANE` (0 — выключить быструю линию), `FAST_INTERVAL` (опрос API без push, сек., по умолчанию 1),
`FAST_PUSH_POLL` (опрос-страховка при работающем push, по умолчанию 3), `FAST_AUDIT_INTERVAL` (сверка со страницей, по умолчанию 15),
`API_BASE`, `WS_URL` (адреса API и WebSocket, если сайт переедет), `SCAN_INTERVAL` (период проверки страницы, сек., по умолчанию 5), `SITE_URL`, `LIST_MAX`, `EXPIRED_KEEP`, `EXPIRED_TTL_HOURS`, `USER_AGENT`, `BROWSER_CHANNEL`
(`chromium` — «новый headless», тяжелее), `TIMEZONE`, `LOGIN_TIMEOUT`.
